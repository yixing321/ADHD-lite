## 2. P0：三个必须先修的真问题（**已全部修好，下面是当时的诊断记录**）

### ✅ P0-1 换一次配色就把快捷键写坏 → 下次启动变成 `Ctrl+=`（"快捷键老是被改回去"的根因）

**这不是玄学，日志里已经完整复现：**

```
15:42:57  settings.json 不存在，使用默认设置  →  Ctrl+Num+（内存里）
15:42:57  启动异常（仅记录）：热键未注册        ← 录入窗还没显示，热键压根没注册
15:43:01  已保存快捷键设置  {"ver":4,"mods":0,"vk":0,"label":"Ctrl+Num+","theme":0}   ← 点配色，写进 0/0
15:43:01  已保存快捷键设置  {"ver":4,"mods":0,"vk":0,"label":"Ctrl+Num+","theme":2}
15:43:05  拒绝注册 VK00                      ← 录入窗终于显示，读到 0/0，注册失败
15:43:08  注册 Ctrl+= -> True / （临时降级，未写入设置）
15:43:11  已保存快捷键设置  {"ver":4,"mods":2,"vk":187,"label":"Ctrl+=",...,"theme":3}  ← 再点配色，把"降级值"写盘
```

**两个成因叠加：**

1. `src/Program.cs:1446 SaveSettings()` **无条件**写 `hotkeyMods / hotkeyVK`；而这两个变量在热键注册成功前是 `0`。
2. 换配色的两处都调用 `SaveSettings()`：`src/MainWindow.cs:404`（设置页色块）、`src/Program.cs:1768`（悬浮球右键"换配色"）。
3. `src/Program.cs:677` 热键注册挂在 `popup.SourceInitialized` 上，但启动时只 `ShowMain("list")`（`src/Program.cs:487`），**录入窗没显示 → 热键一直没注册**。于是"启动后第一次换配色"必然写 0/0。

**后果链**：设置坏 → 启动注册失败 → 降级 `Ctrl+=` → 用户再换配色把降级写死 → 以后每次都 `Ctrl+=`。这也是为什么之前"强制默认 Ctrl+Num+"（ver=4）修了也没用。

**建议修法（2 行 + 1 处时序）：**
- `SaveSettings()` 里改成 `settings.mods = hotkeyRegistered ? hotkeyMods : settings.mods;`（vk 同理），绝不写 0。
- 启动时就注册热键：`new WindowInteropHelper(popup).EnsureHandle()` 后立即 `AttachHotkey()`（`registeredHwnd` 判断已能处理句柄重建）。
- 顺手：`settings.json` 读到 `vk==0` 时直接丢弃、回落到默认。

### ✅ P0-2 下拉菜单类小窗必崩（`InvalidOperationException`）

```
15:43:16  UI 线程异常: System.InvalidOperationException: 在 Window 关闭时，无法将 Visibility 设置为 Visible…
          在 System.Windows.Window.OnDeactivated(EventArgs e)  ← 栈顶就是 OnDeactivated
15:43:59  （同样一次）
```

**成因**：时间单位菜单 / 改期菜单同时挂了 `w.Deactivated += delegate { w.Close(); }`（`src/Program.cs:865`、`:918`），而菜单项点击里又调了一次 `w.Close()`（`:852`、`:904`）。第一次 Close 进到关闭流程，失活事件再次触发 → 二次 Close / Show → 抛异常。

**建议修法**：加 `bool closing` 标志，或点击里改为 `w.Hide(); w.Close();` 前置 `w.Deactivated -= ...`；更干净的做法是给这两个菜单一个统一的 `PopupMenu` 帮助类（顺带解决"每次都要手写 30 行相同的定位代码"）。

### ✅ P0-3 `build.cmd` 已经编不过（漏了 `MainWindow.cs`）

实测（用 `build.cmd` 里同样的 csc 参数，只是换输出路径）：

```

## 4. P2：工程债与一致性（不影响主流程，但会持续制造"改了这里坏那里"）

1. **两套清单实现并存**：`src/Program.cs:2042` 起的旧清单窗（540×640「我的清单」，含 `BuildListWindow / RefreshList / listCount`）已经没有任何入口（`ShowList()` 在 `src/Program.cs:2020` 已改为 `ShowMain("list")`），是纯死代码 —— 约 135 行，删掉能少一半误改风险。
2. **1.5 秒长按的残留**：热键现在直接 `ShowPopup()`（`:2553`），但 `HOLD_MS / holdTimer / holdStartTick / holdSawDown / ScheduleShowPopup / SHOW_DELAY_MS` 全留着（`:2547-2581`），只剩 `--test-delay` 自检在用。日志里还会打"已安排 1.5 秒后弹出"，容易误导排查。
3. **提醒窗里点"完成"不刷新主界面**：`ResolveCurrent()`（`:1082`）只 `SaveTasks + UpdateSummary + HideReminder`，没有 `RefreshMain()` → 主界面开着时，那条任务仍显示待办，直到下次交互。这就是 26-⑤ 的同类残留。
4. **Topmost 靠定时器打补丁**：录入窗 500 ms 后取消置顶（`:1249`）、提醒窗每 600 ms 抖一次共 12 次（`:1141`）。时序脆弱，是目前"有时不跟鼠标/有时压不住别的窗口"的根源。
5. **别名热键**：`Ctrl+=` 成功时会额外注册 `Ctrl+Shift+=`（`:1531`，HOTKEY_ID2），会**悄悄吃掉别的软件的这个组合**，建议去掉或给开关。
6. **文案不一致**：旧清单空态写死"按 Ctrl+="（`:2167`）；README 里的 72 KB / 长按 1.5 秒 / 本周五·下周一 / "v0.2 进度" 均已过时；`docs/主界面.png` 还是 10-23 20:05 的老截图（清单分页、侧栏配色都和现在不一样）。
7. **可删体积**：`_electron_fallback\` 369.5 MB、`_script_fallback\` 空壳。
8. **没有 git**：2900 行单文件 + 十几轮"用 PowerShell 正则替换改源码"的改法，一次误替换就可能没法回退。
